What the scan checks

Signals across the repository.

Rules inspect source, manifests, automation, metadata, and archives before target code runs.

01

Install and execution paths.

Lifecycle scripts, build hooks, custom registries, unsafe binaries, and download-to-execute chains.

02

Credential-shaped data.

Tokens and secrets are identified without printing sensitive values.

03

Obfuscated behavior.

Entropy, encoded payloads, eval chains, invisible characters, and string shufflers.

04

Context for review.

Documentation and test fixtures are recognized. Evidence is ranked instead of flattened into one warning level.

Interpretation

Four scan outcomes.

A finding is evidence, not an accusation. Each verdict states what happened and whether coverage completed.

Rule provenance

Signed offline intelligence snapshots.

Scans do not update themselves. You choose when to download a signed public snapshot, inspect its status, or roll back.

Coverage limits

Incomplete is reported as incomplete.

A timeout, file limit, permission error, or unreadable archive prevents a clean conclusion.

10 minDefault timeout
100,000Default file limit
50 MiBDefault per file
3 levelsArchive depth

These defaults are adjustable. They are not detection guarantees.

Before the scan

Common questions.

Does “No findings” mean the repository is safe?

No. It means the completed scan matched no enabled rule. Static analysis can miss malicious behavior and can report harmless code.

Does repyy execute target code?

No. It reads target files as data. It does not install packages, build the project, run tests, or import source.

Can I scan private repositories?

Yes. HTTPS clones can use supported provider tokens. SSH remotes use your existing SSH agent.

Can a repository weaken its own scan?

No. Repository-owned .repyy.yaml files are ignored. Pass a configuration file you trust with the --config flag.
