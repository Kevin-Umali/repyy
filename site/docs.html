Documentation

Scan unfamiliar code.
Then decide what runs.

repyy is a read-only preflight scanner for local folders and Git remotes. It reports suspicious files, install behavior, dependencies, secrets, obfuscation, backdoors, and data theft patterns.

What repyy does not do

It does not install packages, build the target, run tests, execute source, or upload your code.

Install and run a first scan

Install only the scanner. The target repository remains data throughout the scan.

Homebrew
brew install --cask Kevin-Umali/tap/repyy
Go
go install github.com/Kevin-Umali/repyy/cmd/repyy@latest

Scan a local folder

Terminal
repyy scan ./assignment

Scan a remote repository

Terminal
repyy scan https://github.com/org/assignment
Private remotes

HTTPS clones can use GITHUB_TOKEN, GITLAB_TOKEN, or BITBUCKET_TOKEN. SSH remotes use your existing SSH agent.

Use repyy for a take-home assignment

Keep the target unexecuted until you have reviewed the scan. A remote scan lets you inspect an assignment before creating a working checkout.

1
Scan the Git URL

Start with repyy scan URL. Remote targets use a temporary shallow clone by default.

2
Review the evidence

Read blocking and review findings first. Check every location, confidence level, and reported coverage limit.

3
Choose the next action

Continue in an isolated environment, ask the interviewer for context, or stop. A scan does not prove that code is safe.

Keep the boundary clear

Do not install dependencies, open the repository with workspace trust enabled, build it, or run its tests before review.

Read a verdict

The verdict describes the strongest outcome and whether coverage completed.

No findings

The completed scan matched no enabled rule. This does not prove the repository is safe.

Review required

One or more findings need a person to inspect their context.

Do not run

High-confidence critical behavior appeared in executable, install-time, or CI code.

Scan incomplete

A timeout, limit, permission, clone, archive, or read error reduced coverage.

Targets and history

Pass one or many local paths and Git URLs. For large review queues, put one target per line in a file.

Multiple targets
repyy scan ./repo-a ./repo-b
Target file
repyy scan --file repositories.txt --jobs 4

Remote scans use temporary shallow clones by default. Increase history depth only when you need it.

Full history
repyy scan URL --history all --keep-workdir

Choose a report format

TerminalInteractive review with prioritized findings--format terminal
JSONStructured automation and archival input--format json
SARIFCode-scanning integrations--format sarif
HTMLPrivate, self-contained offline review--format html
Save JSON
repyy scan ./repo --format json --output report.scan.json
Render later
repyy report report.scan.json --format html --output report.html
Evidence handling

Reports escape and redact matched source lines. Treat every report as sensitive because paths and behavior can still reveal repository structure.

Use trusted configuration

Repository-owned .repyy.yaml files are ignored so the target cannot weaken its own scan. Pass configuration you control.

Validate
repyy rules validate examples/repyy.example.yaml
Use config
repyy scan ./repo --config trusted-rules.yaml

Custom rules use declarative regex and path matches. They cannot run commands. Suppressions use stable fingerprints, require a reason, and can expire.

Set policy for automation

The default failure threshold is high. Display filters change what you see, not the verdict or exit code.

Critical only
repyy scan ./repo --fail-on critical
Focused review
repyy scan ./repo --min-severity high --min-confidence high

Install the optional agent skill

The skill tells a coding agent to scan unfamiliar repositories before execution, keep source local, and report incomplete coverage. It installs instructions only. Install the repyy executable separately.

Interactive
npx skills add Kevin-Umali/repyy --skill repyy
Codex, global
npx skills add Kevin-Umali/repyy --skill repyy -g -a codex -y
Separate installs

These commands do not install repyy and do not install dependencies from the repository being scanned.

Privacy and network behavior

  • No telemetry, analytics, accounts, or source upload.
  • Local targets need no network access.
  • Remote targets use the network only to clone the repository you requested.
  • Scans never update intelligence automatically.
  • Provider tokens stay out of clone URLs and use process-local Git configuration.

Inspect signed offline intelligence

repyy ships with a dated offline intelligence snapshot. Updates are explicit and activate only after signature, schema, date, and record validation.

Status
repyy intel status
Update
repyy intel update
Rollback
repyy intel rollback

Inspect the built-in rule set without contacting an external service.

Explain a rule
repyy rules explain CICD-003

Detection coverage

The built-in map covers behavioral combinations and individual indicators across source, manifests, automation, metadata, and archives.

  • Dynamic execution
  • Obfuscation
  • Package lifecycle
  • Malicious dependencies
  • Download and execution
  • Backdoors
  • Credentials and secrets
  • Network and exfiltration
  • Reverse shells
  • Cryptomining
  • CI and editor execution
  • Containers and Git metadata

Review the default limits

Timeout10 minutes per repository
Files100,000 per repository
File size50 MiB per file
Archive depth3 nested levels

Dependency and cache directories are excluded by default. Add --include-dependencies when those files belong in your review.

--file PATHRead more targets, one per line.--format FORMATterminal, json, sarif, or html.--output PATHWrite the report to a file.--jobs NScan 1 to 128 repositories concurrently. Default 4.--config PATHLoad trusted rules and suppressions.--include-dependenciesInclude dependency and cache directories.--history N|allSet remote history depth. Default 1.--keep-workdirRetain remote checkouts after scanning.--fail-on LEVELSet low, medium, high, or critical. Default high.--timeout DURATIONSet a per-repository timeout. Default 10m.--max-files NSet the file limit.--max-file-size BYTESSet the per-file byte limit.--detail MODEsummary, review, or all.--progress MODEauto, plain, or quiet.--color MODEauto, always, or never.--min-severity LEVELFilter displayed findings.--min-confidence LEVELFilter by low, medium, or high confidence.--group-by FIELDGroup by severity, file, or rule.
